# blog-support-codex

CodexでSEO/AIO向けブログ記事を作成するためのルールセットです。

## 共有リポジトリからの開始

同じブランチ・コミットを取得してリポジトリをCodexの作業対象にし、新しいチャットで開始します。初回は `bash scripts/setup.sh` で共通の.venvを準備します。次の入力で、過去のチャットを知らないユーザーも同じ手順から開始する設定です。

```text
このリポジトリのAGENTS.mdとWORKFLOW_CONFIG.jsonに従って、サイトに合う記事を作成してください。
```

共通設定はWORKFLOW_CONFIG.jsonが正本です。入口のAGENTS.mdは8KiB以内に保ち、詳細な執筆方針をARTICLE_RULES.mdへ分離しています。`.venv/bin/python scripts/doctor.py` のcommitとworkflow_fingerprintで、ユーザー間のルール差を確認できます。

画像生成・Web検索の可否は各Codex環境で確認が必要です。詳細な初期設定、制限、診断入力はSHARED_START.mdを参照してください。PRの変更を利用するには、そのブランチを取得するか、mainへのマージ後に最新のmainを取得します。

## 本文の文字数

通常記事は1記事ごとに読者向け本文5000文字以上を必須にし、5000〜8000文字を目安に作成します。中心記事・関連記事・アフィリエイトなしの記事にも同じ条件を適用します。明示的な短文指定がある場合だけ例外とします。

文字数は推定せず、Markdownパーサーを使うチェックツールで測定します。タイトル・見出し・URL・画像alt・コードブロック・空白・PR定型文は含めません。不足する記事は具体例・手順・判断基準・注意点などで補強してから再測定します。実測値と合否は管理情報・台帳・記事ログへ記録します。

```bash
bash scripts/setup.sh
.venv/bin/python scripts/check_article_length.py articles/<slug>/article-body.md
```

測定ツールの終了コードは合格0、文字数不足1、読み込みエラー2です。測定できていない記事を、完成版や測定済みとして提示しないルールです。

## サイトに合う記事と関連記事の自動作成

現在は自由人ブログ（https://jiyoujin.com/）のカテゴリーと方針をSITE_PROFILE.mdに設定しています。タイトルを入力しなくても次の依頼で選定から進めます。

自動選定は、副業ライフ、ノマドライフ、暮らしの工夫、自己投資、ブログラボの5カテゴリーとそのサブカテゴリーに限定します。アフィリエイトなしの情報記事と関連記事にも同じ条件を適用し、各記事の読者課題・適合理由を管理情報へ記録します。一般的なレシピ、芸能・占い、医療・美容解説、物件投資などへ自動で広げません。商品紹介が不要な記事は、情報記事として作成します。

```text
サイトに合う記事を作成。アフィリエイトリンクが取得できない商品は公式URLを入れ、登録・提携先URLも表示してください。
```

タイトル入力時も、既定では中心記事と関連記事を合計5記事作成します。各記事を順番に品質確認し、articles/<slug>/article-body.mdとarticle-info.mdへ保存して台帳・ログへ記録します。途中で「続き」を入力する必要はありません。中断した作業は「続き」で再開できます。

1記事目について本文ファイル、管理用ファイル、アイキャッチ画像、記事内画像の4点を作成・保存し、その記事だけのメッセージで提示します。提示後に2記事目の作成を開始し、同じ順序で5記事目まで繰り返します。次の記事の本文や画像を先に作ることはせず、追加依頼は不要です。

予定記事と各記事の提示状態・提示日時・4点の保存先はARTICLE_BATCH.jsonへ記録します。最後は完了件数とログを簡潔に示し、5記事分の成果物をまとめて再掲しません。中心記事のコピー用Markdown全文は記事1の提示時に表示します。

## 記事と同時に画像を作成

各記事につきアイキャッチ1枚・記事内画像1枚を、利用可能な画像生成ツールで生成し、articles/<slug>/images/へ保存する設定です。プロンプトも管理情報へ残します。実画像の保存先・alt・挿入位置・生成状態を記録し、保存した記事内画像を本文のMarkdownへ挿入します。

WordPressへ投稿する際は画像をメディアへアップロードし、本文のローカル画像パスを公開URLへ変更します。公開画像URLをチャットに貼り付けて反映を依頼できます。アイキャッチはWordPress側のアイキャッチ設定で指定します。

画像生成ツールが利用できない、生成や保存に失敗した場合は、その記事の不足を提示して停止します。画像2点が揃わないまま次の記事の作成は始めません。「未生成の画像を作成」で画像から再試行できます。「画像なし」「プロンプトだけ」を明示した場合のみ、指定に合わせた成果物を提示して継続します。このルールセット自体に画像生成エンジンやWordPressへの画像アップロード実装は含まれていません。

```text
この記事だけ作成：初心者向けのブログの始め方と続けるコツ
```

単記事を指定した場合は1記事です。既定値はSITE_PROFILE.mdで変更できます。タイトル案だけを求めた場合は案だけを出します。

内部リンクは既存の公開済み記事を優先します。新しい関連記事の予定URLと挿入位置は管理情報へ保存し、公開後に「関連記事の公開URLを反映」と依頼して本文へ挿入します。記事ファイルの生成はWordPressへの公開ではありません。

## 記事完成後のアフィリエイト連携

提供元は固定しません。A8.netなどのASP、Amazonアソシエイト、楽天アフィリエイトなどを扱います。

1. 利用可能な成果計測リンクがあれば使用し、取得できない商品は確認済み公式URLを本文へ入れて公開用の記事を作成します。
2. 本文とは別に、商品ごとのアフィリエイト登録・提携先URLをチャットと管理情報へ表示します。案件詳細が確認できなければ登録・検索入口と検索する商品名を示します。
3. 記事を投稿後、提示された提携先で登録・提携し、取得した成果計測URLをチャットへ入力します。
4. 対象商品の公式リンクを差し替え、PR表記・管理情報・ログを更新します。差し替え済みの本文全文をMarkdownコードブロックで再出力し、.mdファイルでも保存します。

公式URLは読者向け、登録・提携先URLは運営者向け、成果計測URLは提携後に本文へ使うリンクです。三者を区別し、仮リンクは使いません。

取得した成果計測URLの入力例：

```text
この記事にアフィリエイトURLを反映
対象記事：記事のタイトルまたはslug
商品名：紹介した商品名・型番
Amazon：取得済みのアフィリエイトURL
楽天：取得済みのアフィリエイトURL
```

片方だけでも、他のASPのURLでも利用できます。直前の記事・商品が明確ならURLだけの入力も扱えます。対応が不明な場合は対象商品を確認します。通常の商品ページURLではなく、ご自身のアカウントで取得した成果計測リンクを指定してください。

同じ商品にAmazon・楽天の両方のリンクを併記できます。一部のURLだけを受け取った場合は、その商品のリンクを差し替え、残りの公式リンクを維持します。再入力時の重複を防ぎます。台帳を手作業で編集する必要はありません。

これは貼り付け用記事ファイルの更新です。WordPressへの自動反映、アカウント登録、提携申請、広告リンク発行、成果同期の実装は含まれません。リンク反映手順はAFFILIATE_LINKING.md、商品台帳の項目はAFFILIATE_RESEARCH.mdに定義しています。

## Markdown保存と本文の履歴

チャットのコピー用コードブロックには記事本文だけが入り、管理情報・提携先URL・ログは別に表示します。保存したarticle-body.mdには外側のコードフェンスを含めません。

ARTICLE_LOG.mdで記事名、更新日時、公開状態、リンク状態、保存先、URL差し替え履歴を確認できます。ARTICLE_LOG.jsonには操作データを記録します。初回の公式リンク付き本文と更新後の本文・管理情報はarticles/<slug>/history/0001/のような版別フォルダへ保持します。日時は日本時間です。

この変更時点では記事ファイルがこのリポジトリにないため、記事ログは空です。チャットや別の場所の過去記事は、自動で取り込んだことにはしません。今後の作成・更新から記録します。

## 使い方

このフォルダをCodexの作業ディレクトリとして開き、記事テーマやアフィリエイトサービスを入力します。

記事タイトルだけでも作成を開始します。「記事を書いて」という追加命令は不要です。

```text
初心者向けのブログの始め方と続けるコツ
```

タイトルを明示する場合は、次の形式も使えます。

```text
記事タイトル：Canva Proのメリット・デメリットを初心者向けに解説
```

入力例：

```text
アフィリエイトサービス：
Canva Pro
```

```text
5記事：
1. note 始め方
2. note 書き方
3. note 収益化
4. note 注意点
5. note おすすめ運用
```

```text
副業 ブログ 始め方
```

Codexは `AGENTS.md` を入口として読み、必要に応じて以下の外部ルールを参照します。

- `OUTPUT_FORMAT.md`
- `QUALITY_GATE.md`
- `CATEGORY_RULES.md`
- `IMAGE_RULES.md`
- `SITE_PROFILE.md`
- `AUTO_CONTENT.md`
- `AFFILIATE_RESEARCH.md`
- `AFFILIATE_LINKING.md`
- `ARTICLE_INDEX.json`
- `AFFILIATE_CATALOG.json`
- `ARTICLE_LOGGING.md`
- `ARTICLE_LOG.md`
- `ARTICLE_LOG.json`
- `ARTICLE_BATCH.json`

## 期待する動作

記事作成依頼を受けた場合、Codexはルール説明ではなく記事作成を実行します。

記事タイトルを入力した場合は、指定タイトルを中心記事として保持し、SITE_PROFILE.mdの設定に従って関連記事まで作成します。単記事指定の場合は1記事を完成させます。読者層や構成はタイトルから補います。商品紹介はAFFILIATE_RESEARCH.mdに従い、広告関係と取得済みリンクを確認します。

単記事では5記事分の情報は不要です。関連記事URLが未指定でも作成を進め、内部リンクは「なし（関連記事URL未指定）」として管理情報に記載します。

5記事展開が自然なテーマでは、5記事テーマ案、パーマリンク案、URL案、内部リンク設計を作成し、記事1から順番に完成させます。

完成記事は、WordPress本文貼り付け用と管理情報用に分けて出力します。

## 重要な方針

- WordPress本文貼り付け用には読者向け本文だけを入れる
- 管理情報、画像プロンプト、記事スコアは本文に混ぜない
- 広告関係がある商品紹介には、成果計測リンクが未取得でも広告・PR表記を入れる
- 条件不足があれば停止せず、修正してから完成版を出力する
- 足りない情報がある場合は、質問を1〜3個に絞る
